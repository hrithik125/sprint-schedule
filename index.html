DSA patterns roadmap — click to expand
Week 1
Hashmaps + frequency maps
~30%
Core insight: If you need to check if something exists, count occurrences, or group things — reach for an object/Map first. Turns O(n²) brute force into O(n) almost always.

Key intuition: "Can I trade memory for time by storing something I've already seen?"
Two Sum Valid Anagram Group Anagrams Top K Frequent Contains Duplicate
Week 2
Two pointers
~15%
Core insight: Instead of nested loops (O(n²)), place one pointer at each end and move them inward based on a condition. Works on sorted arrays or when you're comparing elements.

Key intuition: "Can I avoid the inner loop by moving two indices smartly?"
Valid Palindrome Two Sum II Container With Most Water 3Sum
Week 2
Sliding window
~10%
Core insight: For problems about subarrays or substrings of size k, slide a window across instead of recomputing. Expand right, shrink left when a condition breaks.

Key intuition: "Is this asking about a contiguous chunk that changes as I move through the array?"
Max subarray avg Longest substr no repeat Min window substring
Week 3
Recursion
~15%
Core insight: The function does one small thing, then calls itself on the rest. Always define: base case (when to stop) + recursive case (what to do + call self).

Key intuition: "Can I solve this if I assume the function already works on a smaller version of the problem?"
Factorial Flatten nested array Deep clone Power of two
Week 3
Trees (BFS + DFS)
~10%
Core insight: Trees are just recursion with structure. DFS = go deep first (recursion or stack). BFS = level by level (queue). DOM problems are tree problems.

Key intuition: "DFS when I care about paths or depth. BFS when I care about levels or shortest path."
Max depth Invert binary tree Level order traversal Same tree
Week 4
Mixed pattern drills
timed
The goal: Given a new problem, identify the pattern in under 2 minutes before coding. That's the skill.

Week 4 rule: 25-minute timer. No hints. Name the pattern first. Talk through complexity after. One problem done deeply beats ten rushed.

Interview prep — Gamehok gap list
Critical ▶
Optimistic UI: update UI immediately → fire API → on failure rollback + toast. Keep a previousState ref. Build a like button that rolls back. (Mon/Tue)
Race conditions + AbortController: cancel previous fetch in useEffect cleanup. Build a debounced search. Throttle network in DevTools to test. (Wed/Thu)
TypeScript — type vs interface: interface extends + declaration merging, type for unions/intersections. Know Partial, Pick, Omit, Record, ReturnType. Stop saying "I haven't used TS much." (Fri)
Promise concurrency: browsers allow ~6 parallel HTTP/1.1 connections. Promise.all fires all at once. Build a function that fetches N URLs max 3 at a time. (Sat)
Persistent state: state resets on app close. Layers: in-memory → sessionStorage → localStorage → server. Chat history = fetch from server on mount, sync new messages immediately. (Sat)

DSA: Recursion + trees Prep: System design RADIO NeatHunt: Polish + demo-ready
Recursion feels like magic until you see it: the function does one small thing and calls itself on the rest. Trees are recursion with structure. DOM problems are tree problems. On prep: this is where Osmos rejected you — system design structure.
DSA — recursion + tree basics
Week 3 pattern ▶
Day 1: Recursion only. Factorial + Fibonacci. Draw the call stack on paper. Don't code until you've drawn it.
Day 2: Flatten nested array — recursion on real frontend data. This is a legit interview question.
Day 3: Max Depth of Binary Tree — your first tree. It's just: 1 + max(left depth, right depth). That's it.
Day 4: Invert Binary Tree — swap left and right recursively.
Day 5: BFS — Level Order Traversal. Use a queue, not recursion. Important for DOM-level problems.
Day 6: Implement deep clone — real frontend problem, uses recursion + type checking.
Key rule: always draw the tree or recursion tree before writing a single line of code.

DSA — timed mixed pattern drills
25 min timer ▶
Every problem: set a 25-minute timer. No hints. Attempt first. Then understand what broke.
Before coding: name the pattern. If you can't name it, think for 5 minutes before writing code.
Mix: 2 hashmap problems, 2 two-pointer, 1 recursion, 1 tree problem across the week.
After each: explain your solution out loud as if in an interview. Say the time and space complexity. If you can't explain it, you don't know it yet.
The goal is not to solve every problem. It's to build the habit of structured thinking under time pressure.

Recurring patterns to watch
Self-qualification habit — You know the right answer, then add "I'm not sure exactly" or "I haven't worked with this much." If you know it, say it clean. Qualifiers belong only when you genuinely don't know.
Jumping to complex solutions — Reaching for Redux when simple state works. Proposing heavy patterns before understanding requirements. Anchor on the problem first, escalate only when needed.
System design structure — Not organizing your answer is what got you rejected at Osmos, not knowledge depth. RADIO gives you the frame. Say the letters out loud as you go through them.
Mock interviews > reading — Consistent finding across both your interview cycles. Every concept you study: do a mock drill within 24 hours of learning it. Passive reading does not transfer to interview performance.
