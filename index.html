4-week plan
DSA: Hashmaps Prep: Gamehok gaps NeatHunt: One feature
The hashmap pattern solves ~30% of easy problems. If you can count things, you can probably beat it with a frequency map. This is your week 1 superpower.
DSA — frequency maps + hashmaps
1 problem/day, deeply
Day 1: Don't code yet. Learn the process above. Do it with a pen on paper — Two Sum.
Day 2: Valid Anagram — count character frequency with an object. Why does a hashmap make this O(n)?
Day 3: Group Anagrams — build intuition: sorted string as a key groups anagrams
Day 4: Top K frequent elements — frequency map + sort
Day 5: Contains duplicate + Length of longest substring without repeating (stretch)
Day 6: Revisit any problem you couldn't solve. Recode from scratch without looking.
Day 7: Rest. Read your solutions and write down the pattern in one sentence each.

DSA: Two pointers + sliding window Prep: React deep internals NeatHunt: Add complexity
Two pointers and sliding window together cover another ~25% of interview problems. The key insight: instead of nested loops (O(n²)), you move two indices smartly to stay O(n).
DSA — two pointers + sliding window
1 problem/day
Day 1: Valid Palindrome — two pointer from both ends, move inward
Day 2: Two Sum II (sorted array) — when array is sorted, two pointers shine
Day 3: Container With Most Water — classic two pointer, understand WHY you move the shorter side
Day 4: Max average subarray — fixed-size sliding window
Day 5: Longest substring without repeating chars — variable sliding window with hashmap
Day 6: Minimum window substring (hard — attempt only, understand approach)
Pattern recognition exercise: given a new problem, identify if it's two pointers or sliding window before coding

DSA: Recursion + trees Prep: System design RADIO NeatHunt: Polish + demo-ready
Recursion feels like magic until you see the pattern: the function does one small thing and calls itself on the rest. Trees are just recursion with structure. DOM problems are tree problems.
DSA — recursion thinking + tree basics
1 problem/day
Day 1: Understand recursion with factorial + fibonacci — draw the call stack on paper
Day 2: Flatten nested array — recursion on real frontend data structure
Day 3: Max depth of binary tree — your first tree problem. It's just recursion + structure.
Day 4: Invert binary tree — classic, understand the pattern
Day 5: BFS (level order traversal) — use a queue, not recursion. Important for DOM-level problems.
Day 6: Implement a simple deep clone function — real frontend problem, uses recursion
Key: always draw the tree/recursion tree before coding. Visualization beats memorization.

DSA: Mixed patterns + timed drills Prep: Full mocks daily NeatHunt: Maintenance only
Week 4 is performance week. Stop learning new things. Start performing under pressure. The goal is to make everything you built feel automatic.
DSA — timed mixed pattern drills
1 timed problem/day
Every problem this week: 25 minute timer. No hints. Then review and understand what went wrong.
Before starting each problem — name the pattern first. If you can't name it, think for 5 minutes before coding.
Mix: 2 hashmap, 2 two-pointer, 1 recursion, 1 tree problem
After each: explain your solution out loud as if in an interview. Talk through time/space complexity.
The goal is not solving every problem — it's building the habit of structured thinking under time pressure.
Interview prep — full mocks + communication
2–3 hrs/day
One full mock per day — alternate coding round and system design round
Project story drills — 90 seconds each, no qualifiers, commit to the answer
Behavioral: pushback story, ownership story, collaboration story — tight and specific
After every mock: one thing you did well, one thing to fix. Write it down. Actually fix it the next day.
NeatHunt — hands off, just maintain
30 min/day max
No new features this week. If something is broken, fix it.
Make sure the 90-second pitch is locked — product decision, technical decision, impact.
